Every behaviour task writes its scenario tests first, named "Scenario: <title>" exactly as in the delta specs, from the
THEN clauses, and watches them fail for the right reason before the code; a guard test and the code it guards are one
task with the red lines recorded in the commit message. Every test the unit breaks is fixed inside its file list;
"unchanged and green" lists tests that must pass without changing their expectations. Shapes and DOM hooks:
design.md → Contracts. New styles use tokens only: no hex/rgb/hsl, no named colour, no clip-path transition, no raw
font size. e2e that touches data starts with `reset`, seeds what it needs, waits for `html[data-hydrated]` (`open`),
calls `calm(page)`, and awaits `countSaves` before any reload after an optimistic write. A test that sets its own
viewport or uses only `request` runs in one project (`test.skip(info.project.name !== …)`). Builders run vitest as
`node_modules/.bin/vitest run <file>`; run `npm run build` once before a scoped `npx playwright test <file>` and check
`ss -ltn | rg :<port>` for a leftover server. `proof:full` (~5 min) runs with `run_in_background`. Each commit
typechecks (`npm run check`). No task is irreversible: 0003 only ever runs against temp and e2e databases here; it
reaches Rue's data when the released tarball is deployed, outside this change, and the tag is pushed by the shipper
under Gate 2.

Waves: serial: tweak (one unit).
