Every behaviour task writes its scenario tests first, named "Scenario: <title>" exactly as in the delta specs, from
the THEN clauses, and watches them fail for the right reason before the code; a scenario an earlier merged task
already satisfies gets a mutation check instead (break the mechanism in the owning file, watch it go red, revert).
Every test a unit breaks is fixed in that unit, inside its file list; "unchanged and green" lists tests that must
pass without changing their expectations. Shared names and test-file owners: design.md → Contracts. New styles use
tokens only: no hex/rgb/hsl, no named colour, no clip-path transition, no raw font size; failures use `var(--error)`.
e2e that touches data starts with `reset`, seeds what it needs, waits for `html[data-hydrated]` (`open`), calls
`calm(page)` unless it tests motion, and awaits `countSaves` before any reload after an optimistic write. A test that
sets its own viewport or uses only `request` runs in one project. Run `npm run build` once before a scoped
`npx playwright test <file>` and check `ss -ltn | rg :<port>` for a leftover server. `proof:full` (~5 min) runs with
`run_in_background`. Screenshots for Gate 2 come from the verifier's run; builders commit none. Only 8.1 is
irreversible.
