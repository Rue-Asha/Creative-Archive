## MODIFIED Requirements

### Requirement: Image storage
Every type SHALL accept an uploaded image (jpeg, png, webp, gif, avif, heif; not HEIC) up to 16 MB, converted with sharp to
WebP (long side ≤ 1600 px, ≤ about 200 KB) and stored as a BLOB in SQLite, and served from `/images/[id]` with a
long-lived immutable cache header. Other files and larger files SHALL be rejected. An image downloaded from a URL
SHALL go through the same conversion.

#### Scenario: Uploaded image is stored as WebP
- **WHEN** `storeImage` gets a 3000×2000 JPEG
- **THEN** the stored row has mime `image/webp`, long side 1600 and at most 200 KB
- **proof:** unit

#### Scenario: Each listed format is accepted
- **WHEN** `storeImage` gets a PNG, a WebP, a GIF and an AVIF generated by sharp
- **THEN** each is stored as WebP
- **proof:** unit

#### Scenario: HEIC is rejected by the server
- **WHEN** `storeImage` gets a HEIF-container file compressed with HEVC (a HEIC photo)
- **THEN** it throws `ImageError('not-image')` and no row is stored
- **proof:** unit

#### Scenario: Unsupported file is rejected by the server
- **WHEN** `storeImage` gets an SVG and a text file
- **THEN** each throws `ImageError('not-image')` and no row is stored
- **proof:** unit

#### Scenario: Image over 16 MB is rejected by the server
- **WHEN** `storeImage` gets 16 MiB + 1 byte
- **THEN** it throws `ImageError('too-large')`
- **proof:** unit

#### Scenario: Image from a URL is stored
- **WHEN** `storeImageFromUrl` gets a URL the remote serves as a PNG
- **THEN** a WebP row is stored and its id returned
- **proof:** unit

#### Scenario: Image is served with caching headers
- **WHEN** `GET /images/<id>` runs for a stored image and for an unknown id
- **THEN** the first answers 200 `image/webp` with `cache-control: public, max-age=31536000, immutable`, the second 404
- **proof:** unit

### Requirement: Image in the entry form
The entry form SHALL offer an image upload on every type that replaces the current image on save, check type (jpeg, png, webp, gif, avif or heif by MIME or extension; `image/heic` and `.heic` are
unsupported) and the
16 MB limit in the browser before uploading (inline errors "Unsupported image type", "Image is larger than 16 MB"),
and show the stored image afterwards. Replacing an image SHALL delete the old image row.

#### Scenario: Upload an image in the form
- **WHEN** a manual look is saved with a mockup photo uploaded
- **THEN** the browser lands on `/entries/<id>` and the edit form's image preview `src` is `/images/<id>`
- **proof:** e2e

#### Scenario: Uploading replaces the current image
- **WHEN** a seeded album with an image is edited and a new photo uploaded and saved
- **THEN** the edit form's image preview has a new id and the old `/images/<old id>` answers 404
- **proof:** e2e

#### Scenario: A .heic file is refused in the browser
- **WHEN** a file named `photo.heic` of type `image/heic` is chosen in the image field
- **THEN** "Unsupported image type" shows and nothing is uploaded
- **proof:** unit

#### Scenario: Replacing an image removes the old row
- **WHEN** `updateEntry` sets a new `imageId` on an entry that had one, and `null` on another
- **THEN** both old image rows are deleted
- **proof:** unit

#### Scenario: Unsupported file shows an inline error
- **WHEN** a `.txt` file is chosen in the image field
- **THEN** "Unsupported image type" shows at the field and Save keeps the current image
- **proof:** e2e

#### Scenario: Oversize file shows an inline error
- **WHEN** a 17 MB file is chosen in the image field
- **THEN** "Image is larger than 16 MB" shows at the field and nothing is uploaded
- **proof:** e2e
